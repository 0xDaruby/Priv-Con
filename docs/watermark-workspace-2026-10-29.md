# Watermark workspace refinement

Owner request: adopt the supplied left page-gallery/right watermark-controls arrangement. Status: implemented and verified locally on2026-10-29. This is an authorized F03 UX refinement, including browser-local PDF previews; it does not begin F05 Crop or Windows packaging.

## Decisions

- Keep one PDF, current F03 text/image/font/overlay/range contracts and backend generation unchanged. No mosaic, underlay, arbitrary fonts, text styling or multiple PDF input added from the reference. Neutral PrivCon tokens and light/dark modes remain.
- Real previews use client PDF.js with packaged same-origin worker/CMaps/standard fonts/WASM as needed. The PDF is supplied as bytes to a dedicated loading task, never a remote document URL. Canvas pages only; no interactive annotation/link/script/XFA layer. Disable system-font fallback. Installed6.4.299 exposes no `isEvalSupported` option and source inspection found no dynamic eval call; do not invent an unsupported option. No server preview session or repeat PDF upload on slider edits. Primary references: [PDF.js examples](https://mozilla.github.io/pdf.js/examples/) and [API parameters](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html); installed types/API are authoritative for pinned6.4.299.
- Limit files to existing upload size, PDFs to existing page count, thumbnails to bounded pixel area; show12 pages at a time with at most two renders concurrently. Release previous-window canvases/tasks. Destroy the document/loading task on File change or unmount and ignore stale work. Local image URL lifecycle belongs to its file, not every option change.
- Live mark placement uses displayed cropped page dimensions and the backend placement equations. Text extents use advance widths and ascender/descender from the installed Helvetica font; SVG constrains text to those extents. Browser glyph shapes can differ, so describe this as placement preview. Preserve image aspect/orientation/alpha and apply opacity. Server output validation remains authoritative.
- Desktop: document toolbar and thumbnail gallery on the left, approximately340px settings sidebar on the right with visible submit action. Compact segmented text/image radio tiles, text/image entry, nine-position radio grid, size/opacity percentages, rotation choice/precise value, margins and page scope. Mobile: responsive vertical layout with no fixed side-panel clipping; native labeled controls and keyboard access. Preview failure is explicit and recoverable, keeps selected PDF/options, and does not fabricate pages.

## Module ownership/contract

- Parent: ConversionTool integration, WatermarkWorkspace wrapper, dependency/assets/legal material, shared numeric Helvetica metrics, documentation, canonical build/browser verification.
- Renderer worker: `frontend/components/conversion/PdfWatermarkPreview.tsx`, `frontend/lib/watermark-preview.ts` and preview-focused tests. Component renders a local preview gallery with page count/window controls and per-page placement overlays; options are controlled by the parent. No backend calls or writes to document storage. Actual loaded count also bounds page selection before submission.
- UI worker: `frontend/components/conversion/WatermarkControls.tsx` and `frontend/app/watermark-workspace.css` only. Props: `{ options: WatermarkOptionFields; onChange(options): void; image?: File; onImageChange(image?: File): void; optionError?: string; pages: string; onPagesChange(value): void; pageError?: string }`. Exports `WatermarkControls`. Same defaults/API fractions and angles as F03. Parent wrapper puts existing replacement/removal/upload actions in the document toolbar and passes conversion readiness/submit.
